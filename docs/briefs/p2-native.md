# P2 brief: remove Dojo at constant compiler

Track CORE of Paved, phase P2. Plan of record: `docs/programme/PLAN.md`; rules: `docs/programme/OPERATIONS.md`, `AGENTS.md`.

## Goal

The contracts of `contracts/` run as native Starknet contracts, with no Dojo dependency, on the same
compiler (scarb 2.13.1, snforge 0.51.2, Cairo 2.13.1). Same game rules: the golden games pass with
their expected values unchanged. Gas is measured against the P0/P1 baseline.

Dojo 1.8 pins Cairo 2.13; leaving it first lets P3 bump the toolchain alone.

## Starting point (main after P1, d8a372b)

- Systems: `systems/account.cairo`, `systems/daily.cairo`, `systems/tutorial.cairo`.
- Components: `components/{emitter,hostable,manageable,payable,playable,tutoriable}.cairo`.
- Models (Dojo `#[dojo::model]`): `models/{builder,character,game,index,player,tile,tournament}.cairo`.
- `store.cairo` wraps the Dojo world; `events.cairo`; the emitter component is a no-op today.
- ~70-75 % of the code is pure logic (types, elements, helpers, model impls) and should not change.
- Measured (P1, docs/measures/baseline.md): a simple open move 47.1M L2 gas; at P0, 76 % of a simple
  move was Dojo world calls.

## Design (yours to complete, write it down first)

1. Write `docs/briefs/p2-native.md` (this brief, committed as the first commit of your PR) and
   `docs/architecture/native-storage.md`: the contract split (one game contract or several), the
   storage layout (`Map`s keyed as the models are today, packed where it is free to do so; no
   structural optimisation, that is P5), events, access control, and how `store.cairo` maps onto it.
   Keep the module layout of the repository (`types/`, `elements/`, `helpers/`, `models/` as plain
   structs with their impls, `components/`, `systems/`).
2. Storage: native `starknet::storage` (`Map`, `Vec` if needed). The `Store` keeps its interface where
   it can, so that the components and helpers change little.
3. Events: real Starknet events (`#[event]`) for every state change the client needs (game spawned,
   tile built, discarded, scored, game over, tournament claimed). Name and fields documented.
4. Access control, your own (no Dojo permissions): owner/admin set at deployment, explicit roles if
   needed, every privileged entry point checked, a player only acts on their own game. List every
   external entry point with who may call it in `native-storage.md`. This part gets a security audit.
5. Tokens: keep the Daily entry payment and prize claim exactly as on main after P1 (ERC20 mock for
   tests). No new economy.
6. Tests: snforge only, `dojo_cairo_test` gone. Port `src/tests/setup.cairo` (deploy the native
   contracts and the mock token), the e2e tests, the golden harness (`tests/golden/harness.cairo`:
   only its store access changes; moves and expected values do not), the gas tests in
   `contracts/tests/` (and their setup copy; keep `scripts/measure.sh check-setup`).
7. Remove: the `dojo` and `dojo_cairo_test` dependencies, `dojo_*.toml`, `manifests/`, `overlays/`,
   `manifest_dev.json`, `abis/` if generated by sozo, the `[[target.starknet-contract]]` external world,
   `allow-prebuilt-plugins`, the sozo scripts. `origami_random`: keep only if it builds without Dojo;
   otherwise copy what is used (with its source and licence named in the file).

## Invariants

- Golden games: `RAYON_NUM_THREADS=1 snforge test golden` passes with every expected value unchanged.
  Never edit an expected value. A golden that fails is a rule change: stop and report it.
- Gas ceilings may only go down; record old/new in `docs/measures/baseline.md` and
  `golden-games.md`. A rise is a stop: report it with figures.
- Toolchain unchanged (scarb 2.13.1, snforge 0.51.2). No bump in this PR.
- No deployment on any public network. A local deploy check on starknet-devnet is welcome
  (`scripts/node/`), it is not required.

## Runs

Pinned binaries (`~/.asdf/installs/scarb/2.13.1/bin`, `~/.asdf/installs/starknet-foundry/0.51.2/bin`),
every run `RAYON_NUM_THREADS=1` under `prlimit --as=8589934592 -- /usr/bin/time -v` (full suite
peaked 4.3 GB after P1). Scope your runs to what you touched (`snforge test golden`, `test_gas_`,
`daily`, `tutorial`, the module you port); the whole suite at the end, and CI on the PR.
