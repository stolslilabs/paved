# Paved: risks

| # | Risk | Phase | Mitigation |
|---|---|---|---|
| R-1 | The native port changes the rules | P2 | Golden games (move sequences with expected score) recorded in P0 and kept identical through P2, P3 and P5; never edited to pass |
| R-2 | Move cost is unbounded: the DFS grows with the game | P5 | Structure state (union-find or equivalent) designed in P5; worst-case move measured and budgeted |
| R-3 | Katana / Madara do not accept Cairo 2.20 classes | P0, P3 | Realised: Katana 1.7.1 and 1.8.0-rc.9 refuse Sierra 1.9.x; starknet-devnet 0.10.0 adopted (D-8); re-check Katana with `scripts/node/run-sample.sh` on a new release |
| R-4 | The seed is predictable, so bots can precompute the best game. Under D-23 the seed is per token, Poseidon(salt, token id), and the token id is the game's own counter, so the next deck is known before a purchase. The selective buyer's edge with the mean held by others: +1.20 at p50, +1.69 at p90, +2.23 at p99, against 0.9. At zero traffic, selection does not pay from p50 to p95 (`docs/measures/selective-buyer.md`) | P8 | A VRF, or a seed revealed after the purchase, removes the selection edge. Whether a VRF becomes a mainnet gate is the owner's question, asked by the PM and open. Accepted by D-3 for now; revisit before paid games in P8 |
| R-5 | #181 has flaws: never deployed (open economy config, open mint, first-caller admin, prize theft by id collision, double-counted supply, locked stakes) | P8 | Not deployed; the economy is rewritten in P8 with an audit (security and economy lenses) |
| R-6 | The 2026 client was built by an unsupervised agent and its promises are unmet | CLIENT | Measure frame time and build before building on it (client P0) |
| R-7 | bun is missing on the VPS, so the client build is unverified there | CLIENT | Install or run the client build where bun exists (the Mac clone, or CI) and make it a merge check |
| R-8 | The default installed snforge (0.61, 0.64) crashes the runner against the pinned `snforge_std` | P0, P3 | Updated: the pair is Scarb 2.20.1 / snforge 0.64.0 with `snforge_std` pinned `=0.64.0` |
| R-9 | Class size limit: Starknet caps a class at 81,920 Sierra felts and 81,920 CASM felts. main's `Daily` is at 98.2 % and `Tutorial` at 91.9 % of the CASM cap (release, 2026-10-07): the next addition to a game contract needs the split (P-25) | P7, P8 and later | Release-profile sizes measured per contract PR; CI guard `scripts/class-sizes.sh` (step of the `build` job) fails above the cap; target <= 90 % of the cap; split a contract rather than squeeze it; a class-headroom note before the P8 design |
| R-10 | Skilled play or a bot earns more than it pays: at `c` 1.222 (sigma 0) the greedy bot buying blind has E[h] 1.369 on the 50 calibration decks and 1.501 on 410 decks, while the calibration population is 25 % greedy, 50 % noisy and 25 % novice and averages 0.9 | before mainnet | Gate "calibration against competent play" (P-54): `c` and `rho` must give E[h] below 1 for the best known bot buying blind; the 0.9 average over a mix that includes novice play does not settle it. E4 does it with Sepolia playtest data. Model estimates (PM request, 2026-10-13): the `c` that brings the blind greedy bot to 0.9 is 0.804 (`slope_bps` 8,037) on the 50 decks, or 0.733 (7,329) on the 410; the mix then falls to 0.59 or 0.54. See `docs/measures/selective-buyer.md` |
